# ルーカス音声常駐AI（lucas-voice）

「ルーカス」と呼ぶと Claude Code が起動し、口頭で指示でき、ルーカスが声で返答する PC 常駐機構。

## 使い方

| 操作 | 方法 |
|---|---|
| 常駐開始（常用・ウィンドウなし） | `start_lucas_headless.vbs` をダブルクリック |
| **起動できてるかの確認** | **通知領域（タスクバー右の ^）に Lucas アイコン（夜色＋ティールのオーブ）があれば稼働中**。起動と同時に出て、終了すると消える。常時見せたいならアイコンを時計の横へドラッグ |
| 常駐停止 | トレイアイコン右クリック →「ルーカスを終了」／`stop_lucas.bat` |
| 常駐開始（デバッグ・ログ表示） | `start_lucas.bat` |

すでに稼働中のときに再度起動しても**二重起動ガードが自動で弾く**（「もう起動してるよ」と喋って終了）。アイコンが既に居るなら押し直し不要。

## トレイアイコン（右クリックメニュー）

| 項目 | 動作 |
|---|---|
| ダッシュボードを開く（ダブルクリックでも） | 管理アプリ起動 |
| バーをテスト表示（3秒） | グラスバーを強制表示——「UIが出るか」の自己診断。外部からは `logs\flash.req` を作っても同じ |
| ルーカスを終了 | リスナー停止（アイコンも消える） |

## 文字起こしモード（push-to-talk・Aqua Voice風）

CCとは無関係に、**普通の音声入力**としても使える:

1. **Ctrl+Alt を押しっぱなし**にして話す（バー:「録音中 Xs — 離すと確定」と経過タイマー表示）
2. **キーを離すと確定** → カーソル位置に貼り付け＋**結果は常にクリップボードにも残る**（カーソルがどこにも無くても、あとから Ctrl+V で取り出せる）

録音が止まる条件は**3つだけ**（クリックや他のキーでは絶対に止まらない——録音しながらクリックで貼り付け先を選べる）:

| 止まる条件 | 動作 |
|---|---|
| Ctrl+Alt を離す | 確定 → 貼り付け |
| バーの ×（録音中のみ） | 録音キャンセル（破棄） |
| 上限 180秒 到達 | 自動確定（残り20秒からバーにカウントダウン） |

- **録音の長さに文字起こしの上限はない**（171秒連続音声で最終文まで出力を実測確認）。上限180秒は暴走防止で、`max_recording_sec` で変更可
- **録音しながら裏で認識が進む**（約20秒ごとに無音の切れ目で分割並行処理）ので、長く話しても離した後の待ちは数秒
- 0.3秒未満の押下は無視（Ctrl+Alt系ショートカットの誤爆防止）

## STTモデル（実測に基づく既定値）

**既定 = OpenVINO + NPU（2026-07-15切替）**。同じ large-v3-turbo int8 を NPU（Intel AI Boost）で回す:

| 構成 | 15秒音声 | 171秒音声 | 一致率 | ロード |
|---|---|---|---|---|
| **NPU（既定）** | **0.4s** | **9.8s (RTF 0.06)** | **95.1%** | **2〜4s**（キャッシュ済み） |
| CPU faster-whisper（フォールバック） | 5.6〜5.9s | 63.5s (RTF 0.37) | 95.2% | 4〜34s |

- **CPUをほぼ使わない**＝文字起こし中もPCが重くならない。認識中の他作業も自由
- **遅延マウント**: アイドル `unload_idle_min`（既定15分）でSTTを解放し**約950MBをOSへ返却**。ウェイク発火/PTT押下の瞬間に裏で復帰（2〜4秒・先読みするので体感ほぼゼロ）。`0` で常駐に戻る
- OpenVINOが死んでも faster-whisper(CPU) に自動フォールバック＝認識は絶対に死なない
- モデル実体: `models\whisper-large-v3-turbo-int8-ov`（公式変換済み・**SHA256を本家と照合済み**）＋NPUコンパイルキャッシュ `models\ov_cache`（2GB。消すと次回ロードが約27分になるので消さない）
- ⚠ 初回だけのNPUコンパイル約27分は実施済み。OpenVINOのバージョンを上げるとキャッシュが無効になり再コンパイルが走る

旧実測（2026-07-12・CPU時代）:

| モデル | 速度(RTF) | 正解一致率 |
|---|---|---|
| large-v3-turbo beam2 | 0.44 | 95.2% |
| kotoba-whisper beam5（旧既定） | 0.65 | 81.4% |

turbo が速さも精度も上。`[stt] model = "kotoba"` で戻せる。`cpu_threads = 8`（論理CPU数と一致＝実測で最適。12/14は逆効果）。

**速度の実測結論（2026-07-14）**: 同モデルのままのデコード設定では速くならない——beam1化は+3%のみ、`without_timestamps=True` は**一致率95.2%→42.9%に崩壊**するので絶対に入れない（長尺の30秒窓シークがタイムスタンプ頼み）。体感を支配していたのは**待機中whisperとのCPU競合**（同じ15秒音声が競合下14〜126秒 vs クリーン5.6秒）で、これはウェイク刷新で構造的に解消済み。さらに速くするなら OpenVINO/NPU 化（ランタイム変更・未着手）。

## 認識ログ（履歴UI）

バーに**カーソルを合わせると ≡ と × が出る**:

- **≡** … 認識ログウィンドウをトグル。文字起こし（ティール）と対話（ブルー）の全認識が新しい順に並ぶ（直近200件・テキスト選択してコピー可）
- **×** … バーを閉じる（リスナーは動き続ける）

バーは **WS_EX_NOACTIVATE** でフォーカスを絶対に奪わない——表示されても入力中のカーソル（キャレット）は消えない。

## ルーカスの声（TTSエンジン）

既定は **VOICEVOX 青山龍星**（ローカル・低音の落ち着いた男声。まひろ指定の「JARVIS系」2026-07-14）。SAPI Haruka は自動フォールバック——**VOICEVOXが死んでいても声は絶対に出る**。

- **声の聴き比べ**: `voice_samples\` に男声候補6本のwav（青山龍星ノーマル/しっとり/囁き・玄野武宏・麒ヶ島宗麟・剣崎雌雄）。ダブルクリックで再生して選ぶ
- **声の変更**: `config.toml` の `[tts] style = <ファイル名末尾のid>` → リスナー再起動（またはルーカスに「〜の声にして」と言う）
- **仕組み**: `tts_engine.py` にリスナー(Speaker)と speak MCP の両方が乗る。VOICEVOXエンジン（`voicevox_engine\`・run.exe・RAM約900MB）は**初回発話時に自動起動して常駐**（初回のみ+30〜40秒）。完全に止めたいときは `taskkill /im run.exe /f`
- **エコー抑制の契約**（speaking.lock / last_speak_end）は tts_engine._play が従来と同一手順で維持——この機構を壊す変更は禁止
- **ライセンス**: 個人利用は自由。合成音声を公開する場合はクレジット「VOICEVOX:青山龍星」等が必要
- ログ: `logs\tts.log`（エンジン自動起動・フォールバックの記録）

## ウェイクワード（瞬時起動・2026-07-14刷新）

「ルーカス」の検出は **vosk（軽量ストリーミング認識・48MB）** が専任する:

- **言い終わった瞬間に発火**（実測0.2〜0.8秒。旧方式=無音1.5秒待ち＋whisper認識5〜15秒 を置換）
- **待機中は whisper が一切回らない** → 部屋の動画・生活音を延々認識してCPUが張り付き、幻聴（「次回予告」等）が履歴に積まれる問題が構造的に消滅。待機時の認識負荷は実時間の2%
- 検証: 合成音声10ケース（男女話者・埋め込み文・近似音の負例）で 10/10、誤発火ゼロ。結合テスト4本PASS
- ウェイク語は `[wake] words`（既定「ルーカス」のみ・**トークン完全一致**）。緩い変種を足すと誤発火するので whisper 用の `[words] wake` とは別管理
- vosk が壊れても旧方式（whisper全文認識）へ自動フォールバック

## 人声ゲート（雑音を文字起こししない・2026-07-15）

**Silero VAD（2.3MB・人声/非人声の判別モデル）が whisper の手前の関門**になる。物音・打鍵・ハム・環境音は認識せず捨てる（まひろ指示「人間が喋ってるときだけ文字起こし」）。

- 実測の分離: クリーン人声 0.49（音量15%でも不変）／雑音全種 0.00 → 既定閾値 `min_speech_ratio = 0.1`
- 破棄はログに `(人声ゲートで破棄 speech=0.02)`、通過は認識行に `speech=0.45` が付く——誤破棄があれば数字を見て閾値を下げられる
- **限界（正直に）**: 動画・TVの「人の声」は音響的に人声なので通る。それも弾くには話者照合（まひろの声だけ通す）が次の段階
- PTT（Ctrl+Alt）は意図的な操作なのでゲート対象外。`[vad] speech_gate = false` で無効化可
- ⚠ Silero ONNX は各チャンクに直前64サンプルの context 連結が必須（無いと実声もほぼ0点）／OpenVINOでは変換不可＝onnxruntime実行

## 下書きの消し方

- **バーの「下書きN」バッジをクリック** → 全消し（ホバーで赤くなる）
- 声で「キャンセル」「下書き消して」「クリア」（短い発話のときだけ有効）

## JARVISモード（音声セッションの人格・2026-07-15）

「ルーカス」で起動したCCセッションは **アイアンマンのJARVIS 風**に振る舞う（この `CLAUDE.md` の人格節で定義——音声セッション専用で、通常のCC作業セッションには影響しない）。呼称「サー」・執事調・静かなウィット（先回り気質は一旦オフ＝まひろ指示 2026-07-15）。声側も VOICEVOX 青山龍星＋JARVIS風FX（`[tts] fx = "jarvis"`）で統一。

## 声のコマンド

| 言葉 | 動作 |
|---|---|
| 「ルーカス」（＋続けて指示も可） | **言い終わった瞬間にバー点灯**→CC起動が裏で進む。「ルーカス、〜して」の続きは従来どおり最初の下書きになる。約30秒で「準備できたよ」 |
| （対話中の発話） | **下書きに溜まる**（自動送信しない） |
| 「これでOK」「送信」 | 下書きをまとめて CC に送信 →「送ったよ」 |
| 「キャンセル」「クリア」 | 下書きを破棄 |
| 「バイバイ」「フィニッシュ」「グッジョブ」 | CC を閉じて待機に戻る |

コマンド語は `config.toml` の `[words]` で自由に変更できる（リスナー再起動で反映）。

## ステータスバー（グラスUI・Siri風リキッド）

常駐中は画面下部中央に小さなピル型バーが常時最前面で表示される（`ui.py`・Tokyo Nightテーマ）:

コンパクトなガラスのピル（312x40）が**タスクバーのすぐ上・中央**に出る。左端の**リキッドオーブ**（Siri風流体）が声を捉えると波打って光る。

| 表示 | 意味 |
|---|---|
| （非表示） | **「ルーカス」と呼ぶかPTTを押すまでバーは一切出ない**（待機中は周囲の音でも出ない） |
| ティール・録音中 Xs | PTT文字起こし録音中（経過タイマー・上限20秒前からカウントダウン） |
| ブルー・対話中 + 「下書き n」 | CCセッション中 |
| パープル・発話中 | TTS再生中（マイクはミュート） |

- ホバーで右端にボタンが出る: **≡**（認識ログを上に展開）/ **◎**（ダッシュボード起動）/ **✕**（録音中=録音キャンセル・通常=バーを閉じる）
- フォーカスは絶対に奪わない（入力中のカーソルが消えない）
- **全ウィンドウの最前面に固定**（2026-07-15 まひろ指示）: 他アプリの「常に手前」窓が上に乗っても、0.5秒以内に検知して topmost帯の先頭へ入り直す（NOTOPMOST→TOPMOST トグル＋HWND_TOP。敵対topmost窓を実画面で打ち負かすテスト済み）。⚠ z-order走査のWin32呼び出しは**argtypes明示必須**——既定c_intだと64bit HWNDが切り捨てられ検知が沈黙する（実測）
- 旧tkバーに戻すには `config.toml` の `[ui] engine = "classic"`、バー自体を消すなら `enabled = false`

### DPI（技術メモ・重要 — 2026-07-13 根治）

バーが「見えない」の真因は DPI だった。pywebview/WebView2 は create_window で **勝手にプロセスを DPI認識化**し、WinForms が窓を **中心固定で DPI倍率拡大**する。以前の「`SetProcessDpiAwareness(2)`＋物理px指定＋CSS zoom」は、この中心スケールと二重掛けになって座標が2.25倍に膨れ、バーが画面外(y=1593)へ飛んで不可視になっていた（＝まひろの「UIが見えない」）。

現在の方針（`glass_bar.py`）:

- **自分では DPI認識を設定しない**（`lucas_voice.py` でも `SetProcessDpiAwareness` を呼ばない）。DPI管理は pywebview に任せる。
- バーは **作業領域から水平中央・下端アンカー**で配置し、サイズ/座標は論理px（312x40等）で扱う。中央＋下端に置けば WinForms の中心スケールに耐えて必ず画面内に着地する。
- **CSS zoom は 1.0 固定**。
- 表示切替は `window.show()/hide()` でなく **Win32 `ShowWindow` 直叩き**（CPU飽和でUIスレッドが飢えても効く）。
- 配置・show/hide は `logs/glass_bar.log` に実測矩形付きで記録される（実機の追跡用）。

⚠ 可視性の検証は必ず **画面キャプチャに写るか**で行う。`IsWindowVisible=True` も `PrintWindow` も画面外の窓で成立するので「描画されている」の証明にならない（一度これで騙された）。

ほか pywebview の罠: `transparent=True` はWindowsで無描画（角丸は `SetWindowRgn`）・既定 `min_size=(200,100)` が小窓を拡張（**論理サイズを渡す**）・**js_api の公開属性にWindowオブジェクトを置くと再帰公開でブリッジ崩壊**（`_`付きで隠す）・`hidden=True` はネイティブHandle生成を遅延（**表示で作る**）・`_get_hwnd` のフォールバックは **自プロセス限定**（同名 "Lucas-Bar" を他プロセスから誤取得する）。

※ `dashboard.py` はまだ旧方式（`SetProcessDpiAwareness(2)`＋CSS zoom）。中央配置・リサイズ可なので画面外にはなりにくいが、サイズずれの可能性は残る。E2Eで要確認、崩れていたらバーと同じ方針へ寄せる。

## 安全装置

- **二重起動ガード**: リスナーは1プロセスのみ。2つ目を起動すると「もう起動してるよ」と喋って終了する
- **ワークスペース固定**: CC は常に `C:\Users\mahim\lucas-voice` で開く（ランチャーのデフォルト値にも焼き込み済み）。実際の cwd は起動毎に `logs\last_cc_cwd.txt` に記録される
- **誤爆防止**: ウィンドウはタイトル完全一致＋前面化を確認できた時だけキー送信

## 調整ポイント（config.toml）

- 認識されにくい → `threshold_floor` を下げる（実測: 発話 rms 0.01〜0.03）
- 物音で誤反応 → `threshold_floor` / `min_voiced_sec` を上げる
- 応答が遅い → `beam_size` を下げる（5→2 で速度優先）
- ウェイクワードの誤認識バリエーション → `wake` リストに追加（例:「ルーカース」）

## ログ・トラブルシュート

- 稼働ログ: `logs\lucas_voice.log`（発話→認識結果が全部残る）
- 認識結果がおかしい時はログの `認識 X.Xs: '...'` を見る。誤認識の定番は `lucas_voice.py` の `HALLUCINATIONS` に追加
- 起動直後の1〜2発話は認識が鈍いことがある（ウォームアップ済みだが OS 側マイク AGC の立ち上がりも影響）
- マイクは **Windows のデフォルト入力デバイス**に追従。Bluetooth ヘッドセットに切り替えた時はリスナーを再起動すること

## 仕組み（1行ずつ）

- `lucas_voice.py` — 常駐。待機=voskウェイク監視 / セッション=音量VAD→faster-whisper（CPU int8）→ 意図分類 → CC制御
- `wake_engine.py` — ウェイク検出（vosk小型ja・ストリーミング・トークン完全一致・RTF0.02）
- `tts_engine.py` — 共有TTS（VOICEVOX 男声＋SAPIフォールバック・エンジン自動起動・lock契約）
- `speak_server.py` — MCP `lucas-speak`（userスコープ登録済み）。CC が `speak(text)` でルーカスの声を出す
- `cc_controller.py` — wt.exe 固定タイトル「Lucas-CC」で CC を起動・クリップボード方式で日本語注入・/exit
- エコー抑制 — TTS 再生中は `~\.lucas-voice\speaking.lock`、再生直後は `last_speak_end` の時刻で二重に自声を破棄
- `CLAUDE.md` — CC セッション側の規約（毎ターン `speak` で要点読み上げ）
